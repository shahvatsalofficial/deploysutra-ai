Functional specification

Users and jobs to be done

PersonaJobFeature
DevOps engineer"What did my change actually alter?"analyze diff with file:line
Platform engineer"Enforce guardrails"rules, profiles, policy --fail-on
Release manager"Can I defend this gate?"gate + reasons, sealed reports
SRE"Can we roll back?"rollback evidence model
Security reviewer"Did exposure or privilege change?"DS-K8S-001..005, 012..015, RBAC rules
CI maintainer"Fail the build, no secrets"exit code 2, offline, no credentials

Journeys

  1. Risky deployment: replicas, image, service account, host networking and privileged flags change. The review lists each change with line numbers and blocks.
  2. Public exposure: Service ClusterIP to LoadBalancer raises DS-K8S-001 and is worded as potential exposure, never verified reachability.
  3. Plan import: exported OpenTofu/Terraform JSON becomes action counts per resource type. A destructive change on a data-bearing type blocks.
  4. Readiness packet: missing rollback evidence blocks even a clean manifest; fully declared evidence still yields HUMAN_REVIEW_REQUIRED.
  5. CI: run offline, exit 2 on BLOCKED, upload the HTML report as an artifact.
  6. Assistant use: ask an IDE agent to run the skills or the read-only MCP tools.

Exit codes: 0 ok, 1 error, 2 BLOCKED (or --fail-on hit), 3 report failed verification.

Non-goals

Deploying, applying, rolling back, contacting clusters or clouds, scanning images, enforcing admission, certifying compliance, rendering Helm/Kustomize.

Acceptance criteria (all covered by tests)

A risky Deployment is detected with line evidence. ClusterIP to LoadBalancer raises a static finding. A missing restore test blocks a clean manifest. A fake secret in a plan never appears in JSON, Markdown or HTML. Unsupported YAML fails explicitly. Repeated runs give identical digests. Remote bind and missing token are refused by the report server.
