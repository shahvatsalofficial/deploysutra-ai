Evidence model and rules

Evidence states

StateMeaningProduced by this tool?
VERIFIED_STATICComputed over the supplied filesYes
EXECUTED_VERIFIEDA separately recorded tool resultNever
DECLARED_NOT_VERIFIEDA person said so; no independent proofYes (rollback inputs)
NOT_TESTEDNo test exists or ranYes (drift, live RBAC)
NOT_RUNNeeds something this tool will not do (cluster, metrics)Yes
NOT_VERIFIEDAuthenticity or approval not establishedYes
FAILEDA check ran and failedAudit
PARTIAL_TRUNCATEDInput larger than the summarised windowPlans

A report never collapses these into "passed".

Seals

integrity.digest is SHA-256 over canonical JSON (keys sorted recursively). It detects edits when compared with a trusted copy. It does not say who produced the report and an attacker can recompute it, so it is not a signature.

Line confidence

exact (parser source map), parent (nearest existing ancestor for an absent field), unknown.

Rule accuracy (recorded)

50 author-labelled cases (31 with expected findings, 19 clean twins): 32 expected findings found, 0 false positives, 0 false negatives. This is a regression corpus written by the author, not an independent benchmark. Real manifests will differ.

Rollback prerequisites

prior_revision, backup_verified, restore_test, rollback_procedure, operator_approval. Each is MISSING or DECLARED_NOT_VERIFIED. ready is always false. A plan, checkbox or script is not proof that data is recoverable.
